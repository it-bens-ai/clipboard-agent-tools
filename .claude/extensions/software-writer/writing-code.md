- `code.primitives` =
  | Call shape | Raw primitive | Helper | Invariant carried |
  |---|---|---|---|
  | Pick the clipboard backend | Ad hoc `command -v` checks at the call site | `_clipboard_detect_backend` (`mcp-server-clipboard/lib/clipboard.sh`) | One `uname -s`-scoped cascade per call; every unmatched OS falls through to `osc52`; no side effects |
  | Send bytes to the clipboard | Calling `pbcopy` / `wl-copy` / `xclip` / `xsel` / `clip.exe` / `clip`, or `_clipboard_write_backend`, directly | `_clipboard_send_stdin <backend> <bytes>` (`mcp-server-clipboard/lib/clipboard.sh`) | Captures the backend's stderr in `$MCP_CALL_TMPDIR/backend-stderr`, which the core removes when the call ends; drops it unread on exit 0; on a non-zero exit prints `Error: backend <backend> failed with status <N>: <stderr>` and returns 1, and still returns 1 when that file cannot be read; returns 1 without running the backend when `MCP_CALL_TMPDIR` is unset. The dispatch it wraps, `_clipboard_write_backend <backend> <bytes>`, writes OSC 52 to `/dev/tty`, never stdout, wraps it in a tmux DCS pass-through when `$TMUX` is set, and returns 1 when `/dev/tty` is unwritable; when `CLIPBOARD_COPY_OSC52_DIR` is set to a non-empty value it hands the sequence to `_clipboard_osc52_handoff` instead, and only with `CLIPBOARD_COPY_HOST=pi`, refusing any other host and treating an empty value as unset; on that path it refuses a missing byte count and a payload over 100000 base64 characters before an encoder runs; an unknown backend name is refused with an error |
  | Hand an OSC 52 sequence to a host without a terminal (Pi) | Writing the sequence to a file by hand | `_clipboard_osc52_handoff <seq>`, then `_clipboard_handoff_note` after the copy summary (`mcp-server-clipboard/lib/clipboard.sh`) | `_clipboard_check_handoff_dir` requires an absolute path that equals its own `pwd -P`. It refuses a missing path, a non-directory, a symlink, a trailing slash, a `.` component, a doubled slash, or a relative path. It also refuses a directory not owned by the user, one writable by group or others, or one whose permissions cannot be read. `_clipboard_write_backend` refuses the payload over 100000 base64 characters before the encoder runs. The file is created by `mktemp` under `umask 077` and its path is left in `_CLIPBOARD_HANDOFF_FILE`, with no note file in `MCP_CALL_TMPDIR`; a failure after the file exists removes it; the `OSC 52 handoff: <file name>` note is the result's last line, which the Pi extension parses |
  | Base64-encode the OSC 52 payload | Raw `base64` | `_clipboard_b64` (`mcp-server-clipboard/lib/clipboard.sh`) | GNU `base64 -w 0`, BSD `base64 \| tr -d '\r\n'`, then `openssl base64 -A`; a failing `base64` or `openssl` fails the call; sets `pipefail` itself, scoped by `local -`, so the BSD pipeline keeps base64's status when the file is sourced without the server; returns 1 when neither exists |
  | Read a tool argument | Hand-parsed JSON | `jq -e` to check that `.text` is a non-empty string, then `jq -j '.text'` into `$MCP_CALL_TMPDIR/text`, which keeps NUL bytes and trailing newlines a bash variable would lose / `jq -r '.path // empty'` inside each `tool_*` function | A missing argument produces an error text result; it is never defaulted |
  | Validate a tool argument's shape | Ad hoc `[[ ]]` checks in the tool function | the tool's `inputSchema` in `mcp-server-clipboard/tools.json`, enforced by `shared/mcpserver_core.sh` before the tool runs | Type, `pattern`, and `additionalProperties: false` are checked by the core; the core refuses a schema using a keyword it does not enforce, such as `minLength` |
  | Validate a file argument | Ad hoc `[[ ]]` chains | the guard chain in `tool_clipboard_copy_file` (`mcp-server-clipboard/lib/clipboard.sh`) | Empty, missing, non-regular, and unreadable paths each get their own error and return 1; an absolute path is enforced by the schema's `"pattern": "^/"` |
  | Dispatch a JSON-RPC tool call | Ad hoc `case` on the tool name | `handle_tools_call` → `tool_<name>()` (`shared/mcpserver_core.sh`) | Tool name validated against `^[a-zA-Z_][a-zA-Z0-9_]*$` (-32602 otherwise); a name `tools.json` does not declare, or a declared name with no `tool_<name>` function, returns JSON-RPC -32601 |
  | Log from the server | `echo` | `log <level> <message>` (`shared/mcpserver_core.sh`) | `server.sh` sets `MCP_LOG_STDERR=1`, so each line goes to stderr; stdout carries JSON-RPC responses only. The core merges a tool call's stderr into its result, so code that runs during a tool call does not call `log` |
  | Reject a blocked Bash command | Ad hoc `echo … >&2; exit 2` | `block_clipboard <tool> <hint>` (`hooks/scripts/lib/common.sh`) | Exit 2 is the deny signal; the message stays host-neutral; on Pi it prefixes only tool names that are not already `mcp__clipboard_copy__*`. The entry scripts call `validate_clipboard_host` (`hooks/scripts/lib/common.sh`) for an unsupported `CLIPBOARD_COPY_HOST`, which exits 1 |
  | Run a hook script from the Pi extension | `spawn` at the call site | `runScript` / `runGate` (`plugins/clipboard-copy/pi/gate.ts`) | Sets `CLIPBOARD_COPY_HOST=pi`; never rejects; a timeout kills the script's process group; `runGate` blocks on exit 2 with the script's stderr, or with a fixed reason when that is blank, allows on exit 0, and blocks on any other outcome with a `failure` the caller reports |
  | Read the PreToolUse command | Ad hoc JSON parsing in the entry script | `parse_hook_input` (`hooks/scripts/lib/common.sh`) | Sets the `COMMAND` global and exits 0 (allow) when the command field is empty |
- `code.di_pattern` = Bash. A tool function `tool_<name>()` receives the JSON arguments string as `$1` and writes its user-visible result to stdout; `run_mcp_server` dispatches it by name when `tools.json` declares the tool. Context enters through environment variables exported at the entry point: `mcp-server-clipboard/server.sh` sets `SCRIPT_DIR`, `SHARED_DIR`, `MCP_CONFIG_FILE`, `MCP_TOOLS_LIST_FILE`, and `MCP_LOG_STDERR`; `hooks/scripts/session-start.sh` resolves its prompt path from its own location. `CLIPBOARD_COPY_HOST` is unset on Claude Code and Codex and `pi` on Pi; both hook scripts exit 1 on any other value. The Pi extension sets it and `CLIPBOARD_COPY_OSC52_DIR` for the server. Clipboard utilities resolve from `PATH`, so tests substitute stubbed executables and a `PATH`-only mock directory rather than mocking calls.
- `code.export_conventions` =
  - A new MCP tool is a `tool_<name>()` in `mcp-server-clipboard/lib/clipboard.sh` plus a schema entry in `mcp-server-clipboard/tools.json`; `tools/list` advertises only the tools that file declares, and `handle_tools_call` runs only a declared tool, so a function without a schema entry is not callable. Read `plugins/clipboard-copy/AGENTS.md` §Navigation before adding one.
  - Hook logic shared by more than one script lives in `hooks/scripts/lib/common.sh`; the entry scripts source it and stay thin.
  - Scripts open with `#!/usr/bin/env bash` or `#!/bin/bash`; `mcp-server-clipboard/server.sh` and `shared/mcpserver_core.sh` run under `set -euo pipefail`, and `lib/clipboard.sh` inherits it by being sourced from `server.sh`.
- `code.footgun_additions` =
  - OSC 52 output must reach `/dev/tty`, or the handoff file when `CLIPBOARD_COPY_OSC52_DIR` is set. Writing the escape sequence to stdout corrupts the JSON-RPC stream.
  - Shared hook and directive text stays host-neutral. Pi-only wording goes in `hooks/prompts/host-pi.md` or behind `CLIPBOARD_COPY_HOST=pi`, as in `block_clipboard`.
  - A tool function's stdout and stderr both become the MCP `content[].text`. Neither `echo` diagnostics nor `log` calls belong in code that runs during a tool call; only the result text and error messages are printed there.
  - The hook launchers resolve the plugin root from `PLUGIN_ROOT` or `CLAUDE_PLUGIN_ROOT` and fail when neither is set. No cwd-relative fallback; `plugin-tests/clipboard-copy/plugin_launch.bats` asserts it.
  - Size is read with `wc -c` and the padding stripped (`tr -d ' '` in `tool_clipboard_copy_file`, `${bytes//[[:space:]]/}` in `tool_clipboard_copy`) because `wc` pads the count differently across platforms.
  - `hooks/hooks.json` carries the hook registration for both hosts. Changing a command there needs a matching assertion in `plugin_launch.bats`.

## Post-Step-6

After editing a `.sh` file, run `shellcheck --shell=bash` on it when ShellCheck is installed, then run `.bats/bats-core/bin/bats -r plugin-tests/`. After editing a `.ts` file, run `npm run typecheck`, `npm run lint`, and `npm test`. CI runs the type-check, lint, and Node tests, then ShellCheck over `plugins`, `plugin-tests`, and `.github/scripts`, then the SDK pin check and BATS on pushes to `main` or pull requests when paths in `.github/workflows/ci.yml` match.
